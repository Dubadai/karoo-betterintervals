How it would work (option B)

1. A card in Notifications

Not riding, at most once a day: BetterIntervals checks GitHub. If there's a newer release, a card appears here (and the count goes up). Never during a ride.

2. Tap it: the Karoo's own App info page

Release notes from GitHub and the Karoo's UPDATE button. Tap UPDATE: the Karoo downloads the APK over Wi-Fi and installs it. Settings and the intervals.icu key are kept.

The card at 2×. Header, text and the action word are ours; the look is the Karoo's.

What I found

  • The Karoo already has an update button for side-loaded apps. An app names a manifest.json in its AndroidManifest (io.hammerhead.karooext.MANIFEST_URL). Settings › Apps › the app then shows About, Release notes and an UPDATE button that installs latestApkUrl. Seen working on our test Karoo for kDouble (screenshot 03).
  • But the Karoo never tells you. It fetches the manifest only when you open that page (logcat). So without our own check, nobody finds the update.
  • We can open that page for the rider: io.hammerhead.action.APP_INFO with packageName opens it (tested). A notification card can only open one of our activities, so a tiny invisible activity hands over to that page.
  • Notifications: SystemNotification(style = UPDATE) puts a card in Control Center › Notifications, like myWindsock's. InRideAlert is for rides only, so we don't use it.
  • Checking goes through the Karoo's own HTTP (Wi-Fi, or the phone over Bluetooth), the same way BetterIntervals already talks to intervals.icu. Headwind and Powerbar (timklge) do exactly this.
  • Releases need one more file: manifest.json next to the APK, made by a Gradle task from the version in build.gradle.kts. URL: …/releases/latest/download/manifest.json.
  • Only builds that have this can be told. 0.5.1/0.5.2 on the Karoos don't name a manifest, so the first version with it still goes the old way (Companion app).
  • ClearWind: its only release is a pre-release, and GitHub's releases/latest skips pre-releases. Rolling this out there needs a normal release (or a fixed URL per release).

Options

A. Karoo's page only. Add the manifest to each release, nothing else. No code; the UPDATE button appears in Settings › Apps, but the rider has to go and look.
B. A + our notification cardRecommended
What's drawn above. Check when the Karoo starts and then once a day, only when no ride is recording; one card per new version (it stays until dismissed or updated). Tapping it opens the Karoo's App info page, where UPDATE installs. Reusable: one file, UpdateCheck.kt, plus a manifest line and the Gradle task, also in karoo-starter/.
C. B, but our own update screen. The card opens a BetterIntervals page (version, notes, Update button that then goes to the Karoo page). More work and a second page saying the same as the Karoo's; only worth it if the Karoo's page ever goes away.
